冪等性は「2回目が何もしない」ことではない

2026-08-16

冪等性を「同じ操作を2回やっても壊れない」「2回目は何もしない」と説明されることが多い。間違ってはいないが、これは結果を述べているだけで、実装が満たすべき条件になっていない。この説明だけを持って実装すると、「2回目に来たら何もしない」分岐を書いてしまう。

よくある説明

2回目の実行では何も起きない。

回数に注目している。

実際の定義

f(f(x)) = f(x)
1回適用した後の状態が、何回適用した後の状態とも等しい。

状態に注目している。

「2回目」が特別なのではなく、回数が状態に影響しないというのが本体。

実装がずれる例

「2回目は何もしない」と読むと、実行回数を数えるコードになる。

  • 実行済みフラグを持ち、立っていたら return する
  • 前回の実行ログを見て、あれば skip する

これは冪等ではなく重複実行の抑制で、別のもの。フラグと現実の状態がずれた瞬間に壊れる。誰かが手で設定を変えても、フラグは立ったままなので直らない。

正しくは、実行のたびに現在の状態を観測して、あるべき状態との差分だけを適用する。2回目に何も起きないのは、差分が無いという観測の結果であって、2回目だから抑制したのではない。

  1. 観測する現在の状態を読む。前回自分が何をしたかは見ない。
  2. 差分を取るあるべき状態と比べる。
  3. 差分だけ適用する差が無ければ、結果として何も起きない。

見分け方

その操作が冪等かどうかは、「2回叩いてみる」では判定できない。途中まで適用された状態から叩いて、正しい状態に収束するかで判定する。

1回目が途中で落ちた後の状態は、未適用でも適用済みでもない。回数を数える実装はここで必ず壊れる。差分を見る実装はここで直る。この「収束するか」という問いのほうが、冪等性の実用的な意味に近い。
