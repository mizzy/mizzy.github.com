差分計算は命令選択である

解釈 出典: explorations/2026-06-10-carina-type-system-type-theory/plan-as-compilation.md §3

IaCの差分エンジンがやっていることは、コンパイラの命令選択(instruction selection)の変種として読める。ターゲットの命令セットが固定されていて、ユーザーはその命令をどれも書かず、エンジンが自動的に選ぶ、という構造が同じだからである。

Carinaのターゲット命令セットはCreate / Update / Replace / Delete / Import / Remove / Move / Waitの8命令である。ユーザーはこのどれも書かない。差分エンジンが、desiredのノードとstateのノードを突き合わせ、各ノードに対して適切な命令を選択する。

命令選択として読むと、複合的な変更の扱いも位置づけがつく。Replaceがcascading updateや一時名を伴うのは、単一の論理的変更が複数命令の定型列に展開される、複合命令のloweringに相当する。コンパイラで一つの高水準演算が複数のマシン命令の定型パターンに落ちるのと同じ構図である。

普通の命令選択との違いは入力にある。コンパイラの命令選択はIRだけを見て命令を選ぶが、差分計算はdesired(ソース由来)とstate(世界由来)の二つを突き合わせて選ぶ。命令選択が二引数であることは、IaCのコンパイルが本質的に増分であることの現れである。

出力側の性質も命令選択に対応する。選ばれた命令の列は純粋な値であり、実行は解釈器(Provider)が動的段階で与える。つまり命令選択の成果物は「効果の自由モノイド(列)」であって、その先に継続が隠れていない。
